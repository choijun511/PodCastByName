# 本地目录切片

范围：本机单人审核工具与公开读取页面。不是可直接暴露到互联网的生产服务。

数据流：公开 RSS → 手动导入 → 名称 / 别名候选 → 管理员核验 → 已批准记录 → /api/people → 现有收听界面。

候选检索不是出场认定，名字出现在描述中只能进入候选。公开界面仅展示已审核记录。变更审核状态可撤回发布，记录不会因再次导入自动获批。

前端：dist/index.html、app.js、style.css；加载目录失败时显示错误与重新加载，不回落到旧静态列表冒充实时结果。关注、待听和音频进度继续设备本地保存。
管理端：dist/admin.html、admin.js；管理密钥仅当前页面内存保存，不写浏览器存储。创建人物、导入 RSS、审核、撤回与查看导入结果。
服务端：server.py；SQLite 持久化，静态文件服务限定 dist 目录。数据库与启动密钥不对静态请求开放。

限制：搜索由 /api/search 在服务端规范化姓名和别名后排序、分页；发现和收听初始化仍加载全目录，服务端目前也采用小目录扫描，尚未完成大规模索引优化。没有定时刷新、账号同步或第三方通知。跨 feed 重发自动归组仅能渐进改善，不宣称全网去重完成。


补录数据：requests保存设备凭据哈希、查询和身份线索、人工状态、最终人物ID与更新时间；request_history保留状态记录。同设备相同规范化姓名与线索复用请求，不同设备记录隔离。公开创建 / 读取接口具有输入上限与同源检查，但尚无公网滥用防护，不作为生产服务开放。访问日志不记录搜索query string。

关注更新：events 为候选首次批准保存递增 seq 和 approved_at（candidate_id 唯一）；一次性迁移既有批准内容。撤回通过实时审核状态过滤，重批不生成新事件。GET /api/updates 的 people/after/limit 参数读取分组后的更新，返回 cursor、latest_cursor、has_more；无 people 时只返回基线。相同 audio 或规范化 source+title 归组，并保留各人物的事件 seq。近期发布指 RSS 发布日期位于首次批准前7天至后1天；其他或缺失日期标为历史补录，这是时间规则而非首发核验。

设备侧保存每位人物关注时的 followCursors 与 readUpdates（已读事件序号）。升级前已有关注在首次成功连接时建立基线，不将存量访谈全部推为新消息。取消后重关重新建立基线。关注页打开 / 手动刷新时读取全部分页；当前小目录实现不适合无限增长的更新流，后续增加窗口与按需加载。没有定时扫描、后台推送或跨设备同步。

RSS来源刷新：复用持久化 runs 作为来源登记簿，按 feed_url+person_id 汇总最后一次检查、最近成功、错误、匹配和新增数；稳定来源ID由这两个字段生成。既有导入无需手动迁移。POST /api/admin/refresh {id} 通过原有管理员鉴权，重跑安全RSS抓取和候选去重；错误保留在来源和运行记录。进程重启时将遗留 running 标记为中断失败。当前仍是单进程同步检查，每次下载并扫描当前RSS，仅增量新增候选，不包含ETag条件请求、缺失单集补抓或后台调度。新候选不自动批准。

AI审核：ai_review.py通过HTTPS模型接口调用两次判断、原文校验，保存ai_reviews；未配置无自动发布，错误和不充分证据保留pending。导入/刷新唤醒后台队列，每批最多10条自动续跑；按元数据+人物+规则+模型指纹跳过已判断内容。moderation.py存设备凭据哈希投票和community_hidden；people与updates查询过滤该表，进而影响搜索和收听目录。管理员review只影响编辑状态，不能取消社区隐藏。匿名设备去重非抗刷身份，正式发布前需升级。规则与限制见MODERATION-POLICY.md。

后台审核：独立线程与SQLite连接，不在HTTP请求中调用模型。服务启动先恢复旧RSS运行记录，再用recover=False创建worker连接，避免误将当前RSS检查标记中断。ai_runtime保存队列状态/心跳；处理后每15秒再次检查。错误按60/120秒退避，累计3次错误后暂停当前内容，避免无限计费。发布前BEGIN IMMEDIATE内复核候选状态、内容、人物资料和community_hidden，再原子写入审核、事件和AI结果。模型等待时不占写锁。单实例本地服务，尚无多worker租约或供应商幂等键。

省钱模式v2替代前述双次判断：intake_rules.py保守模板规则；ai_extractions缓存按标题/描述+模型端点/ID+规则版本的参与者提取；ai_calls在请求前预留每日额度并存usage；intake_demand仅存人物ID/最近需求时间。ai_reviews继续保存人物关联结论。别名全名+身份词匹配在服务端执行，同名歧义暂缓。支持未配置模型时的规则队列，默认模板名单为空。调用次数默认每日20，UTC重置；缓存命中在额度耗尽后仍可处理。当前没有货币预算、Batch API或强模型升级。

# 听谁：本地试用版本

在 macOS Finder 双击项目根目录的 **启动听谁.command**，即可启动并打开测试页面。首次运行可能需要在系统提示中允许打开；也可从项目根目录执行：

```sh
python3 prototype/dev.py start
python3 prototype/dev.py status
python3 prototype/dev.py restart
python3 prototype/dev.py stop
```

访问 http://127.0.0.1:8765/ 。启动器将服务放入独立后台会话，关闭启动终端后仍可测试；重复启动不会创建第二个服务。电脑重启或服务退出后再次运行即可恢复，不安装开机登录项，也不承诺自动重启。`status` 检查 `/api/health` 的服务标识和数据库连接；`stop` / `restart` 仅操作启动器记录且实例身份匹配的进程。原先手动运行的服务需先在原终端关闭，启动器不会误杀占用端口的其他程序。

日志位于 `prototype/.runtime/8765.log`（仅本机当前用户可读）。启动失败会给出日志位置，端口占用会明确提示；可用 `--port 18766 --db /tmp/tingshui-test.sqlite3` 运行隔离目录。日志目前不自动轮转，长期测试可停止服务后清理日志。

审核入口为 http://127.0.0.1:8765/admin.html 。启动器沿用或生成 `/tmp/tingshui-admin-token`（权限600），不会把令牌打印到终端或日志；需要管理功能时仅在本机私下读取该文件并填入管理页。不要将令牌放进 URL 或提交仓库。高级调试仍可前台执行 `python3 prototype/server.py`，但它未配置 `CATALOG_ADMIN_TOKEN` 时会在该终端显示随机令牌，关闭终端也可能停止服务；日常测试请使用启动器。

启动器验收：`python3 -m unittest discover -s prototype -p test_dev.py -v`，使用随机本机端口与临时数据库，验证重复启动、独立会话存活、重启、停止、端口冲突、失败提示和令牌权限，不修改主目录。

数据保存在 prototype/catalog.sqlite3，退出服务不会清空。首次启动从 dist/data.js 迁移原型样本；前端不再读取该文件。以后通过管理界面添加人物、导入RSS并审核发布。再次启动不会重新批准已撤回的种子内容。

审核流程：新增或选择人物 → 导入公开RSS → 查看候选原始页面 → 写明本人参与证据 → 确认发布。名字匹配只是候选；驳回、撤回或退回待核验不会从数据库删除记录。收听页刷新后读取最新审核状态。

测试：

```sh
python3 -m unittest discover -s prototype -p test_catalog.py -v
```

check.cjs 与 check-admin.cjs 是本机 Playwright 验收脚本，使用本机安装路径。check-admin.cjs 使用上述临时令牌，验证既有真实 Acquired 样本。两者不属于可移植CI配置。

边界：仅本机单人审核，未部署。人物搜索使用服务端 /api/search，支持姓名 / 别名规范化、精确优先与分页；发现和收听初始化仍加载完整已审核目录，暂不适合大规模数据。没有全网搜索、定时刷新、账号同步。公开内容只包含已批准出场；未审核候选在管理端可见。不得将当前服务直接暴露到公网。


搜索与补录：搜索结果页可提交人物姓名和身份线索，进入“我的补录请求”查看状态。当前设备的随机凭据保存在浏览器本地，服务端只存凭据哈希；清空站点存储后无法找回原设备请求，此版本尚无账号恢复。请求不会自动触发互联网搜索，由管理页面人工处理。

管理端新增补录队列：可保存查找中、待核验、暂未找到（必填说明）、完成（必须关联已有已批准出场的人物）及重新排队。候选审核仍独立于请求状态，不会因请求“查找中”自动发布。

同名人物：在新增人物时填写不同身份说明即可分别创建；同名同身份不重复创建。搜索同时显示各人的身份与独立出场。

check-requests.cjs 使用隔离测试服务 http://127.0.0.1:18765，需要独立SQLite目录和临时管理令牌。测试内容不会写入8765的正式本地目录。

关注页现在显示关注后新审核通过的出场，可播放、稍后听、标为已读并手动刷新。历史补录单独标记；同一访谈匹配多位关注人物时合并；撤回内容在刷新后隐藏，重复审核不会重置已读。关注时间基线和已读保存在当前设备，升级前已有关注从首次成功连接更新服务开始计算。

更新验收：先运行 python3 prototype/check-updates-server.py，再运行本机 Node 的 prototype/check-updates.cjs，完成后停止测试服务。测试服务使用18765端口、临时数据库和 /tmp/tingshui-admin-token，内含明确标注的合成访谈，不写入主目录。

管理页“已接入的 RSS”支持检查新出场和失败重试。首次导入（包括失败）会登记人物与来源组合；每次展示最近检查、最近成功、错误与新增候选数。检查新来源内容不会改变已有审核结论。静态种子未带RSS地址的节目需要先手动导入一次才能登记。当前每次完整读取RSS并去重入库，没有定时或条件抓取。

check-refresh.cjs 使用 check-updates-server.py 的18765隔离服务，验证来源展示、重复检查、网络错误重试和手机布局。

AI与社区纠错规则见 ../MODERATION-POLICY.md。配置OPENAI_API_KEY与TINGSHUI_AI_MODEL后重启；可选OPENAI_BASE_URL用于兼容服务。每次导入唤醒后台队列，每批最多10条自动续跑，管理页可查看状态，未配置不自动发布。AI费用取决于配置模型。投票达到门槛后从公开页面隐藏该关联，保留数据库记录；设备凭据不等于独立用户。测试：python3 -m unittest discover -s prototype -p 'test_*.py' -v；check-votes.cjs使用独立check-updates-server.py，测试投票不得指向真实目录。

省钱模式v2已替代默认双审：规则优先，单集参与者单次提取并跨人物缓存复用。TINGSHUI_AI_DAILY_CALLS默认20（UTC每天，失败也计数），设0可停止新模型请求；缓存和规则仍可处理。TINGSHUI_RULE_FEEDS是经过验证的精确RSS URL JSON数组，默认空；没有任何真实来源被默认批准为规则模板。搜索或关注的人物优先，剩余候选使用剩余额度。具体入库门槛与限制以MODERATION-POLICY.md最新版本为准。

收听队列：在“我的收听”调整稍后听顺序、移除条目、播放待听队列；播放器提供下一集。连续播放默认关闭，可自行开启并保存到本设备。听完的单集标记完成，不再显示在继续收听；点击重新收听从头播放。自动下一集跳过完成和已撤回条目，不循环回到队首，网络失败时停止衔接并提示。check-queue.cjs使用浏览器拦截的隔离目录和本地WAV，不修改真实数据。

播放器支持15/30/60分钟定时暂停，或在本集结束时停止；定时结束不会继续播放队列。分钟计时按经过时间计算，暂停音频时仍计时；站内切页保持，刷新取消。“本集结束”绑定当前单集，手动切换单集会取消该定时。播放倍速保存到当前设备。浏览器/系统休眠可能延迟页面执行暂停，恢复可执行时会核对截止时间，不承诺系统级准点停止。


2026-09-29体验更新：人物页提供节目、统一语言、年份、未听/收听中/已听完筛选与新旧排序，条件写入URL，可刷新或返回恢复；时间线按节目发布日期展示，各音频版本保持独立。发现页展示领域入口、推荐依据及目录覆盖边界。

已加载的页面每15秒（可见时）检查本地服务，断线后显示启动方法与重连按钮。首次连页面也打不开时，请先双击根目录「启动听谁.command」；网页本身无法启动已关闭的服务。API等待15秒超时；音频加载12秒提示较慢，可继续等待或重试。重连保留本设备关注/队列/进度，刷新页面不会自动播放。

前端验收新增：`check-explore.cjs`（纯逻辑）、`check-explore-browser.cjs`（当前真实目录只读浏览器交互）、`check-trial.cjs`（隔离目录、API故障及90秒WAV，不修改主数据）。沿用这些脚本中当前本机Node/Playwright/Chrome路径；不是可移植CI配置。详细验证范围见 QA.md。
